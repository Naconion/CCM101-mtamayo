# Mission Reflection

This laboratory activity helped me understand how containerization works and how Docker can be used to deploy applications more quickly. Compared with installing an operating system on a Virtual Machine, setting up a Docker container is much faster because a container does not require a complete guest operating system. In this activity, I was able to download the Nginx image and run it as a container using only a few Docker commands. This showed me how containers can make application deployment more lightweight and efficient. The port mapping `-p 8080:80` is necessary because the Nginx web server is running inside the container on port 80, while port 8080 is used on the host to access the service. The mapping connects the host's port 8080 to port 80 inside the container. I was able to verify that the Nginx server was working by using the `curl http://localhost:8080` command and viewing the Nginx welcome page. When the `docker rm` command is used, the Docker container itself is permanently removed. This means the container can no longer be started or managed unless a new container is created. However, removing the container does not automatically remove the Nginx image that was downloaded. Containerization can also improve the way software developers and IT operations teams work together. Developers can package applications and their required components into containers, while IT operations teams can deploy those containers in a consistent environment. This supports the DevOps approach by making deployment and management more organized. Finally, my GitHub portfolio is evolving by adding practical cloud computing activities instead of only written information. This laboratory allowed me to document my Docker commands, screenshots, and experiences, giving me a record of the technical skills I have learned.
