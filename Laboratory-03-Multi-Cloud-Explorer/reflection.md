# Laboratory Activity 3: Mission Reflection

Exploring Amazon Web Services, Microsoft Azure, and Google Cloud Platform side-by-side has provided valuable insight into modern cloud computing. Among the three platforms, Google Cloud Platform (GCP) impressed me the most due to its clean UI and native focus on Kubernetes and advanced AI capabilities. However, researching all three revealed that while their brand names and management interfaces differ, their core foundation is remarkably similar. Each provider relies on identical fundamental building blocks: compute instances, object storage, virtual network isolation, and identity management.

Acting as a Cloud Solutions Consultant demonstrated that technical decisions are rarely made in isolation, they are heavily driven by real-world business requirements. Choosing a cloud provider isn't about picking the most popular name; it depends entirely on a client's existing software stack, growth strategy, and budget constraints. For instance, an enterprise deeply rooted in Microsoft Active Directory will naturally lean toward Azure to save costs and simplify single sign-on. Conversely, a machine learning research startup benefits much more from GCP’s specialized TPU infrastructure and AI tools. Matching technical architecture to specific business needs is the most critical skill a Cloud Solutions Architect develops.

Finally, completing this mission has significantly improved my GitHub Cloud Computing Portfolio. By structuring my repository cleanly with dedicated subfolders, modular Markdown files, and visual evidence through screenshots, I am learning how to present technical information professionally. Documenting Linux command outputs alongside cloud service mappings reinforced how traditional server environments directly translate to cloud virtual machines. Overall, this hands-on evaluation expanded my understanding of multi-cloud strategy and improved my ability to communicate technical recommendations effectively.
