# MISSION REFLECTION #
Working through this lab really helped me understand why object storage is such a game-changer for applications. Object storage is different from block storage. Block storage uses drives that organize data into fixed sectors. These are tightly connected to an operating system’s file tree. Object storage treats each file on its own. It stores the file along with its metadata inside a namespace. This makes object storage more scalable and more efficient when dealing with millions of user-uploaded photos. You don’t have to worry about slowdowns in the directory tree. You also don’t have to worry about running out of partition space. Using Docker made deploying the MinIO storage server. I didn’t have to deal with manual dependencies. I didn’t have to worry about configuration files or operating system conflicts. I was able to start an isolated production-ready storage environment with just one terminal command. Passing configuration settings through environment variables made managing root credentials clean. It made the process easy to repeat.

Throughout the exercise I also got an idea of architecture concepts. For example a "bucket" acts as the container or root folder. A bucket is used to group, secure and organize objects in the cloud. When thinking about how large companies make sure this data never disappears if a physical server crashes it really comes down to redundancy. Big cloud providers automatically copy objects across availability zones. They also copy them across physical data centers. This makes sure there is availability and fault tolerance. Finally finishing these labs has really increased my confidence in using the Linux command line. What used to feel scary, like managing container flags, mapping ports and checking services now feels more familiar and natural. This is because I keep practicing system administration tasks.
